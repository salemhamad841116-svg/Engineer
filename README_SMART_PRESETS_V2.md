# منظومة الأوضاع الجاهزة — Smart Presets Engine v2 (الملحق المحدّث، المرحلة 1)

## ما هذا؟

الترقية الكاملة لمنظومة أوضاع التوليد الجاهزة من النسخة الأولية (4 طبقات) إلى 10 طبقات / 50 ميزة فرعية — بقاعدة بيانات حقيقية بدل السجل البرمجي، وعقد Resolved Preset Bundle موحّد يغذي محسّن الأوامر ومحرك الصور. كل الطبقات تعمل محلياً بتكلفة $0.

## الهجرة 040_smart_presets_v2

جدول `smart_presets` بالمخطط المعتمد حرفياً (إصدار، parent_preset_id، is_system/is_active/is_pinned، category، budget_tier، مفاتيح i18n، wrappers، فيزياء بصرية، ocr_gate_mode، مخطط ضوابط، قواعد تعارض، أوزان قوة رباعية، لهجات مزوّدين، خطافات معالجة، لوحة، متغيرات ثيم، style_seed، share_slug) + البذور السبع Idempotent.

**امتداد مقصود موثّق:** عمود `owner_id` إضافي — قاعدة عزل المستأجرين الثابتة تتقدّم؛ كل استعلام مُقيد بالمالك (الأوضاع النظامية تحمل '').

## المسارات الأربعة (+مسار حذف مساند)

| المسار | الوظيفة |
|---|---|
| `GET /api/v1/presets?q=&category=&lang=` | القائمة من الذاكرة (<5ms)، مثبّت أولاً، بحث بالوسوم والمعرّف والتسمية العربية |
| `POST /api/v1/presets/resolve` | عقد Resolved Preset Bundle كاملاً (Zod) — اختيار manual / brand_lock / auto_detected مع graceful fallback |
| `POST /api/v1/presets/custom` | حفظ مخصص معقّم (يرث الأب عبر parent_preset_id) أو تثبيت عبر `{pin_id, is_pinned}` |
| `GET / PATCH /api/v1/projects/:id/brand-kit` | إدارة قفل الهوية (locked_preset_id + locked_style_seed + palette) |
| `DELETE /api/v1/presets/custom/:id` | حذف ناعم (is_active=0) — تتطلبه بوابة التراجع الآمن؛ يبقى الصف وسلسلة الأبوة |

## بوابات القبول (مُثبتة آلياً في smartPresetsV2Suite — 18 اختباراً)

1. **الهجرة والسرعة:** تشغيل up() مرتين بلا أخطاء، 7 بذور بلا تكرار، قراءة دافئة <5ms (قياس فعلي ~0.01ms، وعبر HTTP 1.87ms).
2. **الاختيار التلقائي وRTL:** «صورة واجهة مقهى تراثي» → regional_heritage (وزن الطراز 3× يتغلب على اسم المجال)، حقن العدسة 35mm وقواعد الاستبعاد، المساحة الهادئة يمين، شارة auto_detected مع البديل commercial_storefront.
3. **حارس التعارض والقوة:** pure_white × dramatic_neon → تحويل تلقائي إلى soft_studio موثّق في conflicts_resolved؛ subtle↔strict يغيّر الوزن (0.4↔1.0) وبصمة SHA-256؛ مثال الملحق `commercial_storefront:v1:balanced:16x9:illuminated_night+luxury` مُعاد إنتاجه حرفياً.
4. **البوابة والمحوّل:** commercial/marketing = always، cinematic/ui_assets = skipped (صفر استدعاء OCR بنيوياً)؛ gemini سردي («shot on 85mm lens») ≠ fal مكثّف (وسوم).
5. **الحفظ والقفل والتراجع:** مخصص معقّم من نص ملوّث → قفل بنفس style_seed والألوان → resolve يرث brand_lock → حذف ناعم → fallback_applied:true إلى الأب النظامي دون أي خطأ 500 → تغيير الإصدار/الضوابط يغيّر cache_key والبصمة.

## قرارات هندسية بارزة

- **وزن الطراز 3×:** كلمة طراز («تراثي») تتغلب على اسم مجال («مقهى») — قرار موثّق لأن طراز المشهد يحدد الهوية البصرية أكثر من نوع المكان، والبديل يظهر في الشارة للتبديل بنقرة.
- **الحذف الناعم** بدل الصلب: يحفظ سلسلة parent_preset_id فلا يضيع مسار التراجع بعد الحذف — وهو ما يجعل البوابة 5 ممكنة بلا خطأ.
- **الأولوية:** preset_id الصريح > قفل الهوية > الكشف التلقائي (التجاوز اليدوي مقدّم دائماً).
- **مفتاح الكاش:** `id:vN:intensity:AxB:mods` بترتيب إدخال الضوابط + بصمة SHA-256 كاملة — أي تغيير إصدار أو ضابط يكسر الكاش القديم عمداً.
